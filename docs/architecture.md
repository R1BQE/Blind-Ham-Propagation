# Архитектура проекта

**Язык:** Русский | [English](en/architecture.md)

## Структура во время работы

Приложение состоит из статического frontend и backend на Python/FastAPI.

- `frontend/` — семантический HTML, адаптивный CSS, обычный JavaScript, манифест веб-приложения и service worker.
- `backend/app/main.py` — создание FastAPI-приложения и регистрация маршрутов.
- `backend/app/api/routes.py` — версионированные HTTP- и WebSocket-маршруты.
- `backend/app/services/` — клиенты источников, преобразование Maidenhead, локальные/региональные отчёты, разбор MQTT, хранение и доменная логика.
- `backend/app/collectors/` — длительно работающие сборщики, включая MQTT-сборщик PSK Reporter.
- `backend/run_local.py` — точка входа локальной разработки; функции завершения локальной сессии не должны попадать в production.
- `tests/` — тесты pytest.
- `scripts/` — скрипты настройки и установки.
- `deploy/` — примеры конфигурации службы и reverse proxy.
- `data/`, `logs/` — рабочее состояние, исключённое из Git.

Перед изменением проверяй фактическое дерево репозитория. Документация описывает обязанности компонентов, но не гарантирует, что каждый модуль навсегда останется по указанному пути.

## Поток запроса

1. Браузер загружает frontend с настроенного URL приложения.
2. JavaScript frontend обращается к endpoint того же origin с префиксом `/api/v1/`.
3. В production Apache отдаёт статические файлы и проксирует API-запросы на Uvicorn, слушающий loopback.
4. FastAPI проверяет параметры запроса и вызывает поставщиков/доменные сервисы.
5. Сервисы получают или рассчитывают данные и возвращают нормализованные структуры с метаданными источника.
6. Frontend отображает ответы в доступных текстовых блоках, таблицах и элементах управления.

Публичный адрес приложения: `https://blind-ham.ru/prop/`. Не открывай production Uvicorn напрямую в публичную сеть.

## Отчёт о солнечной и космической погоде

Маршрут `GET /api/v1/solar/activity` собирает результаты независимых источников:

- глобальные солнечные и геомагнитные показатели NOAA SWPC;
- продукт поглощения NOAA D-RAP;
- солнечный XML-отчёт HamQSL.

Ошибка одного поставщика фиксируется отдельно и не должна удалять результаты остальных. Интерфейс показывает монитор HamQSL и сравнение отдельных пересекающихся показателей NOAA/HamQSL.

Источники не взаимозаменяемы. Сохраняй исходные значения, единицы, время наблюдения, время получения и семантику продукта. Не усредняй показатели ради получения одного числа. Например, K и Kp — разные индексы, а компонент Bz не равен полной напряжённости межпланетного магнитного поля. Выбирать предпочтительный источник можно только после документированного сравнения определения, единицы, времени, географического охвата и качества. Несопоставимые значения показывай отдельно.

## Отчёт для QTH

Локальный отчёт преобразует Maidenhead-локатор в координаты центра ячейки. Затем рассчитывает локальную солнечную геометрию и пытается получить ближайшую ячейку сетки NOAA D-RAP. Ближайшая ячейка не является точным измерением в координатах станции и должна обозначаться как модельная оценка.

Текущая реализация не предоставляет проверенный прогноз распространения КВ для конкретной трассы. Не утверждай, что глобальные индексы или D-RAP сами по себе предсказывают успешность конкретной связи.

## Региональные наблюдения PSK Reporter

PSK Reporter — источник отчётов о приёме от участвующих станций, а не прямое измерение покрытия собственной станции пользователя.

### Область наблюдения

- Центр области задаётся Maidenhead-локатором QTH.
- Радиус по умолчанию — 100 км.
- Координаты рассчитываются от центра ячейки Maidenhead.
- Фильтрация по радиусу использует расстояние по дуге большого круга между центром QTH и центром ячейки локатора соответствующей станции.
- Профиль собственной станции отделён от регионального фильтра наблюдений.
- Локатор описывает область, а не точное положение антенны. Сохраняй исходный локатор и его точность.

### Два независимых направления

Не объединяй направления в одну статистику:

1. **TX — региональные передатчики слышны удалённым станциям:** передающая станция находится внутри области QTH, а удалённый приёмник сообщает о её приёме.
2. **RX — удалённые передатчики слышны в регионе:** приёмник внутри области сообщает о приёме удалённого передатчика.

Ни одно направление не доказывает, что собственная станция пользователя, её антенна или мощность обеспечат такую же связь. Это косвенные региональные наблюдения.

### Сбор MQTT и фильтрация

MQTT-топик PSK Reporter поддерживает фильтры по топикам и wildcard, но не умеет задавать географический радиус. Сборщик получает подходящие по топику spots, разбирает локаторы TX/RX и выполняет географическую фильтрацию локально.

Сборщик:

- подписывается только на настроенные диапазоны и режимы;
- переподключается с задержкой и переносит некорректные сообщения и недоступность брокера;
- хранит нормализованные отчёты в ограниченной SQLite-истории;
- удаляет дубликаты;
- запускается по требованию, пока вкладку наблюдений просматривает хотя бы один посетитель;
- общий для всех посетителей; до переработки координации должен работать один worker Uvicorn.

Публичный HTTP API читает уже сохранённые наблюдения и не должен открывать отдельное MQTT-соединение для каждого запроса. Сессии просмотра координируются через WebSocket; после отключения последнего посетителя сборщик останавливается по тайм-ауту простоя.

## Правила обработки данных

Для каждого внешнего значения или наблюдения сохраняй, если источник их предоставляет:

- название поставщика и продукта;
- время наблюдения в UTC;
- время получения в UTC;
- значение и единицу измерения;
- признаки качества, предварительного/окончательного статуса;
- порог актуальности и признак устаревших данных.

Не объединяй незаметно наблюдения с разным временным разрешением. Не выдавай модельный прогноз за измерение. Не выводи локальные ионосферные условия по удалённому ионозонду без указания станции и расстояния до неё.

## Дальнейшая работа

План проекта находится в [дорожной карте](roadmap.md). Моделирование конкретной трассы, выбор источника по качеству, краткие сводки солнечного монитора и эксплуатационная проверка PWA остаются отдельными задачами. Не описывай запланированные функции как реализованные.

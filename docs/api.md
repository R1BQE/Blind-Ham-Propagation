# HTTP API

**Язык:** Русский | [English](en/api.md)

Приложение предоставляет версионированные маршруты с префиксом `/api/v1`. При локальной разработке базовый адрес обычно `http://127.0.0.1:8765`. В production приложение работает через настроенный reverse proxy.

Документ описывает реализацию в `backend/app/api/routes.py`. Перед тем как считать контракт гарантией совместимости, сверяй его с текущим кодом маршрутов и тестами.

## Проверка состояния

`GET /api/v1/health`

Возвращает краткий объект состояния службы с полями `status` и `service`.

## Солнечная и геомагнитная активность

`GET /api/v1/solar/activity`

Возвращает глобальные данные космической погоды NOAA SWPC, данные D-RAP и солнечный XML HamQSL. Источники запрашиваются независимо. Ошибка поставщика записывается в `errors` и может привести к частичному ответу, не удаляя результаты остальных источников.

## Локальный отчёт QTH

`GET /api/v1/local/report?locator=KP50DB`

Обязательный параметр `locator` — Maidenhead-локатор длиной от 2 до 12 символов. Возвращает географический и солнечный контекст и пытается добавить ближайшую ячейку сетки NOAA D-RAP. Ближайшая ячейка — модельная оценка, а не измерение в точке станции.

## Проверка локатора

`POST /api/v1/locator/validate`

JSON-запрос:

```json
{"locator":"KP50DB"}
```

Возвращает нормализованный локатор и координаты центра ячейки. Некорректный локатор приводит к HTTP 422.

## Географический поиск

`POST /api/v1/geography/lookup`

Принимает массив Maidenhead-локаторов и возвращает страну, регион и ближайший населённый пункт из офлайн-базы `data/geography.sqlite3`. Эта SQLite-база географии остаётся необходимой и не связана с историей спотов PSK Reporter.

## Состояние MQTT-сборщика PSK Reporter

`GET /api/v1/psk-reporter/status`

Возвращает состояние подключения и счётчики живого потока: количество MQTT-сообщений, корректных спотов, некорректных сообщений и ошибок. Счётчики не означают, что споты записываются в постоянное хранилище: история спотов не сохраняется.

## Ручные региональные сессии PSK Reporter

Сбор запускается только явным действием пользователя. Открытие вкладок «Мой район» и «Станции» не запускает сбор автоматически.

### Запуск

`POST /api/v1/psk-reporter/regional/sessions`

JSON-запрос:

```json
{"locator":"KO59XX","radius_km":100,"duration_seconds":60}
```

- `locator` — локатор центра области.
- `radius_km` — радиус больше 0 и не более 1000 км; по умолчанию 100.
- `duration_seconds` — 60, 120, 180 или 300 секунд; по умолчанию 60.

Для запуска MQTT-сборщик должен быть подключён. Если он недоступен, API возвращает HTTP 503. При превышении лимита одновременных сессий возвращается HTTP 429.

### Состояние и результат

`GET /api/v1/psk-reporter/regional/sessions/{session_id}`

Во время сбора возвращает состояние, оставшееся время и количество подходящих спотов. После завершения возвращает агрегированный отчёт с отдельными направлениями TX и RX.

### Страницы станций

`GET /api/v1/psk-reporter/regional/sessions/{session_id}/stations?direction=tx&offset=0&limit=10`

Параметр `direction` принимает `tx` или `rx`. `offset` задаёт смещение, `limit` — размер страницы от 1 до 100. Интерфейс загружает станции страницами по 10.

### Отмена

`DELETE /api/v1/psk-reporter/regional/sessions/{session_id}`

Останавливает активный сбор. Отменённая сессия не выдаётся как завершённый отчёт.

Сессии получают споты из общего живого MQTT-потока. Региональный менеджер фильтрует их по локатору и радиусу и хранит только агрегированные результаты в оперативной памяти. Сырые споты и историческая SQLite-база не используются. Результаты доступны в памяти ограниченное время (10 минут после завершения); перезапуск backend сбрасывает сессии.

## Настройки MQTT-сборщика

Сборщик запускается вместе с backend, если в `settings.ini` параметр `[psk_reporter] enabled = true`. Он подписывается на все поддерживаемые диапазоны и цифровые режимы и передаёт корректные споты активным региональным сессиям. Постоянная история не создаётся.

Для временной диагностики администратор может задать `PSK_REPORTER_TOPICS`. Старый параметр `topics` в `settings.ini` не используется.

## Ошибки

- HTTP 422 — некорректные параметры или данные.
- HTTP 429 — достигнут лимит одновременных региональных сессий.
- HTTP 503 — MQTT-сборщик или региональный менеджер недоступен.
- HTTP 404 — сессия не найдена или срок хранения результата истёк.

При изменении маршрутов обновляй этот документ и соответствующие API-тесты в одном изменении.

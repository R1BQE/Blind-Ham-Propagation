# Blind-Ham Propagation

**Язык:** Русский | [English](README.en.md)

Доступный веб-сервис для радиолюбителей: мониторинг солнечной и геомагнитной активности, контекст для QTH и региональные наблюдения PSK Reporter.

## Возможности

- **NOAA SWPC:** глобальные показатели солнечной и геомагнитной активности.
- **NOAA D-RAP:** оценка поглощения в D-слое; для QTH выбирается ближайшая опубликованная ячейка сетки.
- **HamQSL:** XML-монитор солнечных показателей, расчётных условий на КВ-диапазонах и VHF-явлений.
- **Сопоставление источников:** сравнение отдельных общих показателей NOAA и HamQSL без искусственного усреднения несовместимых значений.
- **Maidenhead:** проверка локатора, расчёт координат, автоматическое определение по геолокации устройства и поиск по адресу через Яндекс Карты.
- **Локальный отчёт:** геометрия Солнца и ближайшая ячейка D-RAP.
- **PSK Reporter:** MQTT/TLS-сборщик, ограниченное SQLite-хранилище и отдельные региональные TX/RX-наблюдения.

Проект развивается. Наличие источника данных не означает, что уже реализован полноценный прогноз радиосвязи. Текущий этап и оставшиеся задачи описаны в [дорожной карте](docs/roadmap.md).

## Быстрый запуск в Windows

Запусти `run-windows.bat`. Скрипт обновит код, подготовит виртуальное окружение, запустит локальный backend и откроет приложение в браузере.

Подробности: [разработка и развёртывание](docs/development-and-deployment.md).

## Ручная установка для разработки

Требуется Python 3.11 или новее.

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e ".[dev]"
python -m pytest tests -q
```

В Debian/Linux вместо активации PowerShell используй:

```bash
source .venv/bin/activate
```

Запуск API вручную:

```bash
uvicorn backend.app.main:app --host 127.0.0.1 --port 8765
```

Для обычной локальной проверки в Windows предпочтительнее `run-windows.bat`: он настраивает дополнительные механизмы жизненного цикла локального приложения.

## Основные API-маршруты

Базовый префикс: `/api/v1`.

- `GET /health` — состояние сервиса.
- `GET /solar/activity` — данные NOAA, D-RAP и HamQSL.
- `GET /local/report?locator=KP50DB` — географический контекст локатора и D-RAP.
- `POST /locator/validate` — проверка Maidenhead-локатора.
- `GET /psk-reporter/status` — состояние MQTT-сборщика.
- `GET /psk-reporter/regional?locator=KP50DB&radius_km=100&hours=6` — региональные TX/RX-наблюдения.
- `POST /psk-reporter/subscriptions` — изменение фильтров сборщика.
- `WS /psk-reporter/session` — сессия активного просмотра радионаблюдений.

Полные параметры, ограничения и коды ошибок: [описание API](docs/api.md).

## Источники и точность данных

- [NOAA SWPC](https://services.swpc.noaa.gov/json/) — глобальные измерения и индексы.
- [NOAA D-RAP](https://www.swpc.noaa.gov/products/d-region-absorption-predictions-d-rap) — модель поглощения в D-слое.
- [HamQSL](https://www.hamqsl.com/solarxml.php) — сводный XML-монитор.
- [PSK Reporter](https://www.mqtt.pskreporter.info/) — реальные отчёты о приёме от участвующих станций.

Измерения, модельные оценки, геометрические расчёты и реальные отчёты о приёме нельзя смешивать. Каждое значение должно сохранять источник, единицу измерения и время наблюдения. D-RAP — не MUF. Глобальные индексы — не прогноз конкретной радиотрассы. Отсутствие PSK Reporter spots не доказывает, что диапазон закрыт.

Подробнее: [источники данных и правила интерпретации](docs/data-sources.md).

## Доступность

Интерфейс разрабатывается с приоритетом клавиатуры и программ чтения с экрана: семантическая HTML-разметка, подписи элементов, видимый фокус, текстовые результаты и сообщения о состоянии. Карты и цвет не должны быть единственным способом получить информацию.

## Развёртывание и обновление production VDS

Публичный адрес приложения: `https://blind-ham.ru/prop/`. Backend должен слушать только loopback-интерфейс; наружу его публикует Apache reverse proxy. Не открывай Uvicorn напрямую в интернет.

Для существующей установки обновление выполняется командой `bp update` от root. Перед обновлением можно проверить состояние через `bp status`; возврат к предыдущей успешно установленной версии выполняется через `bp rollback`. Подробности и ограничения описаны в [руководстве по развёртыванию](docs/development-and-deployment.md).

Первоначальная установка и обновление — разные операции. `scripts/install_vds.sh` предназначен только для первоначальной установки и не заменяет `bp update`.

Не добавляй в Git секреты, локальный `settings.ini`, пользовательские данные, рабочую базу SQLite или журналы.
